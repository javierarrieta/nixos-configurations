# llama-server cache/reuse metric series (Task 5 / Layer 1 instrumentation)

Source: `curl -s "http://localhost:8001/metrics?model=<name>"`.
Captured from host gateway `http://host.containers.internal:8001`.

## Cache-related series (for Grafana panel — out of scope here)

| Series | Type | Meaning |
|--------|------|---------|
| `llamacpp:prompt_tokens_cached_total` | counter | prompt tokens reused from KV cache (primary cache metric) |
| `llamacpp:prompt_tokens_total` | counter | prompt tokens processed, excluding cached |
| `llamacpp:prompt_seconds_total` | counter | time spent processing prompts |
| `llamacpp:n_tokens_max` | gauge | largest observed sequence length (prompt + gen) |
| `llamacpp:n_decode_total` | counter | llama_decode() calls (excl. spec/multimodal) |
| `llamacpp:n_busy_slots_per_decode` | gauge | avg busy slots per decode (batching signal) |

## Supporting spec-decode series (Ling only — Ornith has spec decoding off)

| Series | Type | Meaning |
|--------|------|---------|
| `llamacpp:spec_decode_num_draft_tokens_total` | counter | draft tokens proposed |
| `llamacpp:spec_decode_num_accepted_tokens_total` | counter | draft tokens accepted |
| `llamacpp:spec_decode_num_drafts_total` | counter | draft passes |

Cache reuse here exceeds prompt_tokens_total because Ornith's multimodal
(mmproj) prompts are re-cached across many turns; `prompt_tokens_cached_total`
accumulates across sessions while `prompt_tokens_total` is a rolling window.
